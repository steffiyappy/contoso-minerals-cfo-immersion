Cara membangun demo Fabric opsional

Jalur kecil dan terkendali dari CSV sintetis yang disediakan ke analisis Cowork baru.

Pilih jalur

Opsional, bukan prasyarat. Opsi kerja tersingkat adalah notebook PySpark staging, unduhan CSV bernama dan lampiran manual Cowork. Tidak diperlukan laporan Power BI, model semantik atau Copilot Studio. Tidak ada deployment, publikasi, koneksi tenant atau pengiriman yang dilakukan.

A. Opsi kecil yang berfungsi: 45-60 menit

Lakehouse + notebook + snapshot CSV. Minta admin kapasitas memastikan workspace berkemampuan Fabric dan izin membuat/menjalankan item. Trial Fabric yang diizinkan mendukung data engineering, Lakehouse dan notebook. Ketersediaan trial dikontrol tenant. Data Agent AI dan Copilot tidak didukung pada kapasitas trial. [8]

B. Ekstensi opsional terpisah: sekitar 30 menit

Tambahkan Fabric Data Agent dan, secara opsional, preview Microsoft 365 Copilot setelah tabel berfungsi. Estimasi tidak mencakup persetujuan kapasitas, izin, lisensi, startup Spark dan waktu tunggu akses. Perubahan tenant dapat membutuhkan hingga satu jam. Lewati ekstensi bila akses belum siap. [6, 7]

Bangun

  1. Siapkan workspace demo terpisah, 5-10 menit

    Buka Microsoft Fabric memakai akun organisasi yang disetujui. Pada Workspaces, buka workspace demo baru atau yang diizinkan. Minta admin workspace/kapasitas menetapkan kapasitas aktif dan hanya akses yang diperlukan untuk membuat/menjalankan Lakehouse dan notebook. Jika item tidak tersedia, berhenti dan hubungi admin. Jangan mengubah pengaturan organisasi menyeluruh atau geografis sendiri.

  2. Buat Lakehouse, 3 menit

    Di workspace demo pilih New item, cari Lakehouse, pilih, dan beri nama Mining_Close_Demo. Gunakan skema default dbo bila mendukung skema. Kit hanya menimpa tabel bronze_, silver_ dan gold_ bernama miliknya di Lakehouse ini. Jangan lampirkan Lakehouse produksi.

  3. Ekstrak dan unggah input, 5-8 menit

    Di Windows klik kanan input-data.zip, pilih Extract All, lalu buka folder input-data hasil ekstraksi. Harus ada 15 file CSV serta input_schema.json. Di explorer Lakehouse pilih Files, buat subfolder input-data, buka, lalu pilih Upload > Upload files dan pilih semua 16 file. Jika Upload folder tersedia, unggah folder ke Files. Pastikan hanya satu tingkat input-data: Files/input-data/canonical_ledger_raw.csv. Jangan unggah ZIP sebagai tabel. [1]

  4. Impor dan lampirkan notebook, 5 menit

    Kembali ke workspace. Gunakan entri Import notebook pada toolbar workspace dan pilih 01_Mining_Close_Fabric.ipynb dari komputer Anda. Tergantung tata letak, entri dapat berada di Import > Notebook. Buka notebook hasil impor, pilih PySpark (Python), lalu di Explorer kiri gunakan Add lakehouse untuk memilih Mining_Close_Demo yang sudah ada. Pin sebagai Lakehouse default dan restart sesi setelah mengganti default. [9]

  5. Periksa konfigurasi, 3 menit

    Sel kode pertama mengharapkan /lakehouse/default/Files/input-data. Ini mount notebook Fabric yang didokumentasikan, bukan path Windows. Pada Files Lakehouse, menu file Copy File API path harus cocok. Tanggal sumber 2026-09-09, batas tutup 2026-08-31, dan cakupan hanya beban/capex Juni-Agustus. ERP mentah tetap bronze; CSV canonical staging menjadi silver bertipe. Notebook tidak berpura-pura melakukan seluruh normalisasi ERP dari awal. [2]

  6. Jalankan berurutan, 10-15 menit ditambah startup Spark

    Pilih Run all. Baca penjelasan Inggris/Indonesia sebelum mengubah sel. Assertion skema, hash, presisi desimal dan baseline harus lulus. Jangan lewati sel merah yang gagal, menghapus pengecualian, mengisi FX kosong atau menghapus duplikat berdasarkan SourceRowID. Jika SHA256 gagal, unggah ulang file persis dari ZIP. Snapshot sumber baru memerlukan kontrak serta baseline baru yang ditinjau, bukan assertion yang dimatikan.

  7. Periksa tabel gold dan SQL opsional, 5 menit

    Refresh Tables Lakehouse. Sembilan tabel gold terkelola harus muncul. Baca rekonsiliasi kontrol yang ditampilkan dan pemeriksaan di bawah. Secara opsional beralih ke SQL analytics endpoint, buka New SQL query, tempel 02_Gold_Queries.sql dan jalankan satu SELECT per langkah. Tunggu sinkronisasi metadata bila tabel belum terlihat. SQL memakai kolom gold yang sama dalam skema dbo default. Tidak perlu aset Power BI.

  8. Unduh file ekspor bernama, 5 menit

    Refresh Files > gold_export. Notebook menggunakan penulisan pandas CSV UTF-8 terbatas, sehingga gold_control_reconciliation.csv adalah file tunggal nyata, bukan folder part-file Spark. Unduh sembilan gold_*.csv dan export_manifest.json lewat menu file Download. Unduh seluruh folder bila UI menyediakan tindakan itu. Periksa RunUTC yang sama serta jumlah baris/hash manifest. Jika proses gagal, jalankan ulang sampai berhasil sebelum mengunduh; penulisan lintas tabel/file tidak transaksional.

  9. Lampirkan dan buat analisis Cowork baru, 5 menit

    Di pengalaman Cowork yang disetujui, buat tugas baru lalu gunakan kontrol attach/upload yang tersedia untuk melampirkan unduhan. Jika menerima lampiran file cloud, Anda dapat menempatkan file secara manual pada lokasi cloud yang disetujui lalu melampirkannya. Jika tidak, unggah unduhan langsung. Tidak tersedia penyalinan SharePoint otomatis atau konektor Cowork-Fabric native yang diverifikasi. Tempel prompt yang sesuai di bawah. Tinjau draf; jangan kirim.

Gunakan hanya file hasil penyegaran yang dilampirkan pada tugas ini: gold_source_metadata.csv, gold_control_reconciliation.csv, gold_exception_register.csv, gold_budget_summary.csv, gold_operations_summary.csv, gold_ap_review.csv, gold_bank_cash_reconciliation.csv, gold_supplier_credits.csv dan gold_normalized_ledger.csv. Baca gold_source_metadata.csv terlebih dahulu dan periksa RunUTC serta tanggal sumber/batas tutup yang konsisten pada semua file; gunakan export_manifest.json untuk memeriksa kumpulan ekspor jika tersedia. Jika ada file hilang atau tercampur, berhenti dan minta snapshot konsisten.

Buat analisis BARU dari file ini sesudah penyegaran, bukan narasi lama yang digunakan ulang. Nyatakan SourceAsOfDate, CloseCutoffDate, RunUTC aktual dan cakupan: ledger beban/capex sintetis Juni-Agustus 2026, bukan buku besar lengkap. Menjalankan ulang saja tidak memajukan tanggal sumber. Tampilkan cakupan, jumlah null/akun tidak terpetakan/impor ulang serta selisih controller, prioritaskan tindakan tinjauan berbukti, dan buat ringkasan kesiapan tutup singkat dengan isu terbuka eksplisit. Cantumkan nama file persis, kolom serta SourceRowID/InvoiceID/Ref/EvidenceRef yang relevan.

Pertahankan seluruh 3.012 kejadian ledger yang disediakan dan bedakan 12 impor ulang dari koreksi yang disetujui. Jangan mengisi tiga FX kosong, memetakan lima akun tidak dikenal atau menyelesaikan enam pemasok ambigu tanpa bukti baru yang disetujui. Bandingkan SUM(KnownUSD_AllOccurrences)-SUM(ControlUSD), bukan jumlah selisih baris nullable. Sertifikat controller disimulasikan terpisah, bukan saldo diaudit.

Bedakan eksposur kandidat duplikat dari penghematan kas terealisasi; jangan jumlahkan isu tumpang tindih atau campur mata uang. Perlakukan ons hasil pemulihan sebagai produksi, bukan penjualan atau kas. Pisahkan pelunasan bank berikutnya dari batas tutup. Jangan menyimpulkan sebab-akibat, ketahanan kas, persetujuan jurnal, pendanaan atau penutupan. Ini snapshot yang diunduh dan dilampirkan manual, bukan koneksi langsung Cowork-Fabric. Buat keluaran draf untuk tinjauan saja. Jangan kirim, posting, membayar, menyetujui, mengubah data sumber atau membuat rapat.

Pada kit tetap ini, menjalankan ulang membuat RunUTC baru tetapi tanggal sumber tetap sama. Untuk data yang benar-benar berubah, pemilik data harus memberi versi CSV, memperbarui kontrak skema/hash/jumlah input, definisi tanggal sumber serta assertion baseline yang diharapkan, lalu menjalankan semua sel dan mengunduh kembali seluruh kumpulan ekspor. Jangan memberi label terkini pada data lama. Mulai tugas Cowork baru atau ganti seluruh lampiran secara eksplisit sebelum meminta analisis baru. Jangan menjadikan jawaban lama sebagai pengganti bukti terbaru.

Agent opsional

Fabric Data Agent sendiri didokumentasikan tersedia umum, sedangkan penggunaan dari Microsoft 365 Copilot masih preview. Agent native pada chat utama Copilot bukan verifikasi konektor native Cowork. Panduan ini tidak mengklaim koneksi langsung Cowork-Fabric. [5, 7]

  1. Minta admin kapasitas memastikan Fabric berbayar F2 atau lebih tinggi, atau Power BI Premium per-capacity P1 atau lebih tinggi dengan Fabric aktif, geografi yang didukung serta fitur AI yang diperlukan untuk lingkup yang disetujui. Jalur trial di atas tidak mendukung Data Agent AI. Tempatkan Data Agent dan Lakehouse pada region kapasitas yang sama. [4,5,8]
  2. Minta admin tenant/keamanan memastikan pengaturan Copilot/Azure OpenAI dan kapasitas sesuai dokumentasi. Pengaturan pemrosesan dan penyimpanan lintas-geografi berlaku menurut persyaratan lokasi, termasuk kapasitas di luar batas data EU dan US. Jangan aktifkan akses seluruh organisasi atau melewati pembatasan regional/kepatuhan. Dapatkan persetujuan kebijakan untuk kelompok yang dituju. Pengaturan dapat membutuhkan hingga satu jam. [6]
  3. Pada workspace yang sama pilih New item > Fabric data agent, beri nama Mining_Close_Review, lalu tambahkan Mining_Close_Demo dari katalog OneLake. Pilih hanya sembilan tabel gold di atas. Data Agent mengkueri tabel Lakehouse terpilih, bukan file CSV/JSON mandiri. Agent memakai izin Anda yang ada; chat dalam produk tidak memerlukan kunci Azure OpenAI. [4,5]
  4. Buka editor instruksi agent dan tempel 03_Data_Agent_Instructions_EN.txt. Gunakan 03_Data_Agent_Instructions_ID.txt hanya sebagai penjelasan Indonesia yang sepadan. Dukungan bahasa Data Agent yang didokumentasikan hanya bahasa Inggris, jadi eksekusi pertanyaan/instruksi/contoh bahasa Inggris. Tambahkan pasangan pertanyaan/SQL Inggris yang sesuai dari 03_Data_Agent_QA_EN_ID.txt dan 02_Gold_Queries.sql. Ajukan lima pertanyaan uji dan bandingkan dengan hasil yang diharapkan; periksa kueri yang dihasilkan. [4,5]
  5. Gunakan jumlah agregat dan jawaban singkat, bukan permintaan ekspor seluruh baris di chat. Respons Data Agent dapat dibatasi 25 baris dan 25 kolom. Karena itu 26 pengecualian ledger memerlukan kueri/ekspor SQL untuk daftar lengkap. Jika izin atau DLP memblokir data, pertahankan pembatasan dan nyatakan batasannya. [5]
  6. Hanya jika penggunaan Microsoft 365 disetujui: pastikan lisensi Microsoft 365 Copilot ATAU langganan komersial Office 365, ditambah lisensi per-pengguna yang diperlukan untuk setiap pengguna. Minta admin lisensi memvalidasi hak yang tepat; jangan simpulkan dari keberadaan tombol Copilot. Fabric dan Microsoft 365 Copilot harus memakai tenant yang sama serta akun login yang sama. Penerima memerlukan akses ke agent dan sumber data di bawahnya. [7]
  7. Setelah agent tervalidasi, pemilik berwenang dapat memilih Publish serta Publish to Agent Store. Di Microsoft 365 Copilot buka Agent Store dan pilih agent, atau sebut dengan @ pada chat utama Copilot. Jika belum muncul, refresh navigasi dan minta admin M365 memeriksa Copilot extensibility. Ini uji preview terpisah, bukan bagian notebook dan tidak dilakukan oleh kit. Respons dapat keluar dari batas kepatuhan/region geografis Fabric menurut ketentuan penanganan data Microsoft 365. Tinjau tata kelola sebelum publikasi. [7]

Pemecahan masalah dan batas validasi

Path input tidak ditemukan: Periksa Lakehouse default, lokasi Files/input-data dan tidak ada input-data/input-data bertingkat.

Assertion gagal: Berhenti. Unggah ulang isi ZIP yang tidak diubah. Jangan buang pengecualian atau melemahkan pemeriksaan agar lulus.

Tabel tidak muncul di SQL atau Data Agent: Tunggu sinkronisasi metadata, refresh, periksa Lakehouse/skema default serta izin. Gunakan tabel gold terkelola, bukan file mentah atau path Delta eksternal.

Ekspor gagal atau melebihi batas driver: Jangan menaikkan batas 20.000 baris sembarangan. Kit hanya untuk data kecil. Minta engineer menyiapkan ekspor terpartisi/scalable untuk data besar. Jangan sebut folder part Spark sebagai CSV bernama.

Agent tidak tersedia: Gunakan opsi notebook/CSV 45-60 menit. Minta admin memeriksa kapasitas, lisensi, geografi, pengaturan terbatas serta waktu tunggu akses.

Divalidasi lokal, bukan di Fabric. Probe Python Decimal/Fraction memeriksa secara independen total mentah/staging aktual, kandidat kunci gabungan, pencocokan batch, anggaran serta produksi. JSON/sintaks Python notebook dan kontrak kolom SQL diperiksa. PySpark tidak terpasang lokal, dan tidak ada pengujian runtime Fabric, penulisan Delta, endpoint SQL, Data Agent, M365 Copilot atau eksekusi Cowork. Assertion runtime memberi pemeriksaan tambahan ketika Anda menjalankan notebook.
