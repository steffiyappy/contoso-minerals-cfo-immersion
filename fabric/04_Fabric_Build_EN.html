How to build the optional Fabric demo

A small, controlled path from supplied synthetic CSVs to a new Cowork analysis.

Choose a path

Optional, not a prerequisite. The shortest working option is a staged PySpark notebook, named CSV download and manual Cowork attachment. No Power BI report, semantic model or Copilot Studio is required. Nothing has been deployed, published, connected to a tenant or sent.

A. Small working option: 45-60 minutes

Lakehouse + notebook + CSV snapshot. Ask your capacity administrator to confirm a Fabric-enabled workspace and permission to create/run items. A permitted Fabric trial supports data engineering, Lakehouse and notebooks. Trial availability is tenant-controlled. Data Agent AI and Copilot are not supported on trial capacity. [8]

B. Separate optional extension: about 30 minutes

Add a Fabric Data Agent and optionally Microsoft 365 Copilot preview after the tables work. The estimate excludes capacity, permission and licensing approvals, Spark startup and access waits. Tenant switches can take up to one hour to propagate. Skip this extension if access is not ready. [6, 7]

Build

  1. Prepare a separate demo workspace, 5-10 min

    Open Microsoft Fabric with your approved organizational account. In Workspaces, open a new or approved demo workspace. Ask the workspace/capacity administrator to assign an enabled capacity and grant only the access required to create/run the Lakehouse and notebook. If the needed item is unavailable, pause and ask the administrator. Do not change organization-wide or geographic settings yourself.

  2. Create the Lakehouse, 3 min

    Inside the demo workspace choose New item, search Lakehouse, choose it, and name it Mining_Close_Demo. Use its default dbo schema if schema-enabled. This kit overwrites only its named bronze_, silver_ and gold_ tables in this Lakehouse. Do not attach a production Lakehouse.

  3. Extract and upload the inputs, 5-8 min

    On Windows right-click input-data.zip, choose Extract All, and open the extracted input-data folder. It must contain 15 CSV files plus input_schema.json. In the Lakehouse explorer select Files, create a subfolder named input-data, open it, then choose Upload > Upload files and select all 16 files. If Upload folder is available, upload the folder under Files instead. Verify there is only one input-data level: Files/input-data/canonical_ledger_raw.csv. Do not upload the ZIP as a table. [1]

  4. Import and attach the notebook, 5 min

    Return to the workspace. Use the workspace toolbar Import notebook entry and select 01_Mining_Close_Fabric.ipynb from your computer. Depending on the layout, the entry can be under Import > Notebook. Open the imported notebook, choose PySpark (Python), and use the left Explorer Add lakehouse to select the existing Mining_Close_Demo. Pin it as the default Lakehouse and restart the session after changing the default. [9]

  5. Inspect the configuration, 3 min

    The first code cell expects /lakehouse/default/Files/input-data. This is the documented Fabric notebook mount, not a Windows path. In Lakehouse Files, the file menu Copy File API path should agree. The source-as-of date is 2026-09-09, the close cutoff 2026-08-31, and the scope is expense/capex June-August only. Raw ERP remains bronze; the staged canonical CSV becomes typed silver. The notebook does not pretend to perform all ERP normalization from scratch. [2]

  6. Run in order, 10-15 min plus Spark startup

    Select Run all. Read each English/Indonesian explanation before changing a cell. Schema, hashes, decimal precision and baseline assertions must pass. Do not skip a red failed cell, drop exception rows, fill missing FX, or deduplicate on SourceRowID. If a SHA256 assertion fails, re-upload the exact files from this ZIP. A new source snapshot requires a reviewed new contract and baseline, not disabled assertions.

  7. Inspect gold tables and optional SQL, 5 min

    Refresh Lakehouse Tables. Nine managed gold tables should appear. Read the displayed control reconciliation and checks below. Optionally switch from the Lakehouse to its SQL analytics endpoint, open New SQL query, paste 02_Gold_Queries.sql and run one SELECT at a time. Wait for table metadata synchronization if a table is not yet visible. The SQL uses the same gold columns in the default dbo schema. No Power BI asset is needed.

  8. Download the named export files, 5 min

    Refresh Files > gold_export. The notebook uses bounded pandas UTF-8 CSV writes, so gold_control_reconciliation.csv is a real single file, not a Spark part-file folder. Download each of the nine gold_*.csv files and export_manifest.json using the file menu Download. Download the entire folder if your UI provides that action. Verify a common RunUTC and the manifest row counts/hashes. If a run failed, rerun successfully before downloading; cross-table/file writes are not transactional.

  9. Attach and generate a new Cowork analysis, 5 min

    In the approved Cowork experience, create a new task and use its available attach/upload control to attach the downloaded files. If your experience accepts cloud file attachments, you may manually place the files in your approved cloud location and attach them there. Otherwise upload the downloads directly. No automatic SharePoint copy or verified native Cowork-Fabric connector is supplied. Paste the matching prompt below. Review the draft; do not send it.

Troubleshooting and validation boundary

Input path not found: Confirm the default Lakehouse, Files/input-data location and absence of nested input-data/input-data.

Assertion failure: Stop. Re-upload the unchanged ZIP contents. Do not discard exceptions or weaken checks to get a green run.

Tables missing in SQL or Data Agent: Wait for metadata synchronization, refresh, verify Lakehouse/default schema and permissions. Use managed gold tables, not raw files or external Delta paths.

Export fails or exceeds driver bound: Do not raise the 20,000-row bound blindly. This kit is small-data only. Ask an engineer for a partitioned/scalable export for larger data. Never call Spark part folders a named CSV.

Agent unavailable: Keep the 45-60-minute notebook/CSV option. Ask the administrator to verify capacity, licensing, geography, scoped settings and access waits.

Validated locally, not in Fabric. Python Decimal/Fraction probes independently check actual raw/staged totals, compound-key candidates, batch matching, budgets and production. Notebook JSON/Python syntax and SQL column contracts are checked. PySpark is not installed locally, and no Fabric runtime, Delta write, SQL endpoint, Data Agent, M365 Copilot or Cowork execution was tested. Runtime assertions provide additional checks when you run the notebook.
